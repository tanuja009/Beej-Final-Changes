# Beej Sangh Procurement Portal — User Stories

User stories with acceptance criteria for every module built so far. Acceptance criteria list the validations and messages implemented in the wireframe.

**Total: 70 stories in 15 modules.**

## 1. Authentication & Profile

| Story ID | Story Name | User Story | Acceptance Criteria |
|---|---|---|---|
| AUTH-01 | Login with NCD ID & Password | As a Society Head or Beej Sangh Admin, I want to log in with my NCD ID / username and password, so that I can reach my own dashboard. | AC1. The Login page shows two role tabs: "Society Head" and "Beej Sangh Admin".<br>AC2. Three login methods are offered: "NCD ID & Password", "Mobile OTP" and "Email OTP".<br>AC3. The NCD ID field is shown only for the Society Head role. Username and Password are shown for both roles.<br>AC4. A "Security Verification" (CAPTCHA) block is shown above the "Login to Portal" button.<br>AC5. On login, a Society Head lands on the Society Dashboard and an Admin lands on the Admin Dashboard.<br>AC6. Changing the login method resets any OTP step that was in progress.<br>AC7. The page has a "Forgot Password" link and a "New Society Registration" button. |
| AUTH-02 | Login with Mobile OTP | As a portal user, I want to log in with an OTP sent to my mobile, so that I can log in without a password. | AC1. The mobile field accepts digits only, maximum 10 digits.<br>AC2. The mobile must be 10 digits starting with 6-9, else: "Enter a valid 10-digit Indian mobile number (starts with 6-9)."<br>AC3. On "Send OTP", a 6-digit OTP is generated and "OTP sent successfully to +91 XXXXXX1234" is shown (only the last 4 digits are visible).<br>AC4. The OTP is valid for 30 seconds. "Resend OTP" is disabled with a countdown (" in Ns") and becomes active after 30 seconds, showing "(OTP expired)".<br>AC5. OTP shorter than 6 digits: "Please enter the 6-digit OTP."<br>AC6. Expired OTP: "OTP has expired. Please resend OTP."<br>AC7. Wrong OTP: "Invalid OTP. Please enter the correct OTP. (N attempts left)". After 5 wrong attempts: "Maximum attempts reached. Please resend OTP."<br>AC8. Resend creates a new OTP, the old OTP stops working, and the toast "A new OTP has been sent." is shown.<br>AC9. Correct OTP: toast "Mobile number verified. Logged in successfully." and the user lands on the dashboard of the selected role.<br>AC10. "Change Mobile Number" returns to the mobile entry step. |
| AUTH-03 | Login with Email OTP | As a portal user, I want to log in with an OTP sent to my email, so that I have another way to log in. | AC1. The email must be in a valid format, else: "Please enter a valid email address."<br>AC2. The confirmation shows a masked email (first 2 characters, then X, then the domain).<br>AC3. OTP length, 30-second validity, resend, 5-attempt limit and error messages are the same as AUTH-02.<br>AC4. Correct OTP: toast "Email verified. Logged in successfully." and the user lands on the role dashboard. |
| AUTH-04 | Forgot Password | As a user who forgot the password, I want to reset it using my mobile number and an OTP, so that I can log in again. | AC1. The page shows 3 steps: Mobile Number, Verify OTP, New Password.<br>AC2. The mobile must be exactly 10 digits, else: "Please enter a valid 10-digit mobile number".<br>AC3. After sending, the page shows "OTP Sent Successfully!" with the mobile number. "Resend" sends a new OTP.<br>AC4. OTP not 6 digits: "Please enter a valid 6-digit OTP". Wrong OTP: "❌ Invalid OTP! Please try again."<br>AC5. New password must be at least 8 characters: "Password must be at least 8 characters long".<br>AC6. Confirm password must match: "Passwords do not match!"<br>AC7. Success: "✅ Password reset successfully! You can now login with your new password." and the user returns to Login.<br>AC8. "Back to Login" returns to Login and resets the steps. |
| AUTH-05 | Reset Password (logged in) | As a logged-in user, I want to reset my password with OTP verification, so that my account stays secure. | AC1. The page opens from the user menu option "Reset Password".<br>AC2. Current password is required: "Please enter your current password".<br>AC3. The OTP is sent to the registered mobile number, which is shown read-only.<br>AC4. OTP and new-password rules and messages are the same as AUTH-04.<br>AC5. Success: "✅ Password reset successfully! Your password has been updated." and the user returns to the dashboard. Cancel also returns to the dashboard. |
| AUTH-06 | Change Password | As a logged-in user, I want to change my password from My Profile, so that I can update it at any time. | AC1. "Change Password" on My Profile opens a popup with Current Password, New Password (minimum 8 characters) and Confirm New Password.<br>AC2. Any field empty: "Please fill all fields".<br>AC3. New password under 8 characters: "New password must be at least 8 characters long".<br>AC4. Passwords do not match: "New passwords do not match!"<br>AC5. Success: "✅ Password changed successfully! Your password has been updated." and the popup closes.<br>AC6. Cancel, ✕ or a click outside the popup closes it without changes. |
| AUTH-07 | Update Profile with OTP | As a logged-in user, I want to update my profile after OTP verification, so that only I can change my details. | AC1. My Profile shows Full Name*, Username (read-only), Mobile Number*, Email, Role and Status (read-only). A Society Head also sees Society Code and Society Name (read-only).<br>AC2. "Update Profile" switches to update mode with a "Send OTP" button.<br>AC3. Mobile must be 10 digits before sending the OTP: "Please enter a valid 10-digit mobile number".<br>AC4. OTP not 6 digits: "Please enter a valid 6-digit OTP". Wrong OTP: "❌ Invalid OTP! Please try again."<br>AC5. Name, Mobile and Email are required: "Please fill all required fields".<br>AC6. Success: "✅ Profile updated successfully! Your changes have been saved." and the new name shows in the header.<br>AC7. Cancel leaves update mode without saving. |
| AUTH-08 | Logout and Session | As a logged-in user, I want to log out, so that nobody else can use my session. | AC1. Logout is available in the sidebar footer and in the user menu.<br>AC2. Logout clears the session and shows the Login page.<br>AC3. Refreshing the browser while logged in keeps the user on the same page. The Login page itself is not remembered. |

Only approved societies can be made members: "Only approved societies can become members."<br>AC4. Toasts: "<name> is now a Member." and "<name> set to Non-Member." |

Columns: Crop, Date, Season, Variety (with 2nd / 3rd choice), Requested, Approved, Pending, Payment, Status, Actions, Invoices.<br>AC2. Status: Under Review, Pending, Approved, Partially Approved, Hold or Rejected from the admin decision. It becomes Dispatched or Received from the dispatch order.<br>AC3. Payment: Pending, Advance Paid (25%), Fully Paid or Received. A rejected demand shows Pending.<br>AC4. "Pay Full" is shown only when the advance is paid, the demand is not fully paid, and the admin has decided.<br>AC5. Society Name, Society Code, District and Block are read-only.<br>AC2. Procurement Year, Demand Date (default today) and Season (Kharif, Rabi, Summer) are entered.<br>AC3. There is no Save Draft button. Buttons are Cancel (back to the list) and Preview. |

Changing the crop clears all three choices.<br>AC6. Second and Third choices are alternates and do not change the quantity or amount. |
| DEM-04 | Raise Demand – Quantity, Packets & Price | As a Society Head, I want to enter quantity in Kg as packet multiples and see the price per Quintal and the total amount, so that I know what I will pay. | AC1. "Quantity Demanded (Kg)" is entered by the user.<br>AC2. A note under the quantity shows the crop's packet sizes, e.g. "Note: Packets of this crop are of 8 Kg, 10 Kg, 20 Kg. Enter the quantity in multiples of these packet sizes only."<br>AC3. Packet sizes come from Seed Packaging Management for that crop. If none are set, 8, 10 and 20 Kg are used.<br>AC4. The quantity must be a whole multiple of one packet size. Otherwise an inline red message shows, e.g. "Quantity must be a multiple of 8 Kg / 10 Kg / 20 Kg.", Total Amount is cleared, and Preview is blocked with an alert.<br>AC5. Empty quantity on Preview: "Please enter the quantity demanded."<br>AC6. "Price per Quintal (₹)" is auto-filled from the crop's Breeder Seed rate in Seeds Rate Management (per Kg × 100). The same season and Active rate are preferred. The default is ₹24 per Kg.<br>AC7. "Total Amount (₹)" = Quantity (Kg) × rate per Kg. It is not multiplied by the number of varieties.<br>AC8. Expected Date of Delivery defaults to today. |
| DEM-05 | Demand Preview | As a Society Head, I want to preview my demand before paying, so that I can check it. | AC1. The preview shows Season, Crop, the variety choices, Requested Quantity (e.g. "800 Kg (8 Quintal)"), Rate per Quintal, Total Amount and Advance Payment Required (25%).<br>AC2. Buttons: Back and "Payment Now". |

The Payment Summary shows Society, Crop / Variety, Second and Third Choice, Quantity, Rate, Total Amount, "Balance (75% on delivery)" and "Advance Payment (25%) Due Now". It says "Invoice will be generated after payment".<br>AC2. Payment modes: UPI Payment (with UPI ID), Net Banking (with bank list), Debit Card and Bank Challan.<br>AC3. No mode selected: "Please select a payment mode".<br>AC4. On payment, one demand is created (DEM-2024-NNN) with status "Under Review" and payment "Advance Paid (25%)". Procurement Year, Demand Date, Expected Delivery and all choices are saved.<br>AC5. The success screen shows Transaction ID, Payment Mode, Amount Paid, "✓ Advance Paid" and an invoice download.<br>AC6. The payment is recorded in Payment History as "Advance (25%)". |
| DEM-07 | Full (Balance 75%) Payment | As a Society Head, I want to pay the remaining 75% after approval, so that my demand is fully paid. | AC1. Before approval: "Full payment is available once the demand is approved."<br>AC2. Already paid: "This demand is already fully paid."<br>AC3. The preview shows Advance Already Paid (25%), Balance Payment Due (75%) and the note "After payment, the full invoice (100%) will be generated."<br>AC4. After payment, the demand becomes "Fully Paid", the success screen shows "✓ Fully Paid", the Full invoice is generated, and Payment History records "Balance (75%)". |
| DEM-08 | Demand Details & Invoices | As a Society Head, I want to view a demand and download its invoices, so that I have a record. | AC1. The View popup shows exactly the Raise Demand form fields: Society Name, Society Code, District, Block, Procurement Year, Demand Date, Season, Crop, First / Second / Third Choice Variety, Quantity Demanded (Kg), Price per Quintal, Total Amount, Expected Date of Delivery.<br>AC2. "25% Invoice" is shown after the advance payment and "Full Invoice" after the full payment.<br>AC3. Advance invoice not available: "Advance not paid yet." Full invoice not available: "Full payment not completed yet."<br>AC4. Invoices download as Invoice-Advance-25pct-<id>.html / Invoice-Full-<id>.html. |

## Known Wireframe Limitations

These items are placeholders in the wireframe and need real implementation:

- CAPTCHA is a placeholder box; it does not generate or check a code.
- Login does not check the username / password against saved users.
- OTPs are demo values shown on screen; no SMS or email is sent.
- Search fields on Society Member List, Admin Society Members and the Breeder Seed Demand list are not connected yet.
- Dashboard and Reports figures are static demo numbers; report PDF / Excel buttons only show a message.
- Data is kept in the browser only and resets on reload (except society registrations and logins, which use local storage).
